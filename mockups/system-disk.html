Layout & data notes

  • 位置：Disk 是第三张卡，整行铺满——390px 宽下 2 列格子里塞不下 1.4 TB / 1.9 TB · 528 GB free；也避免把现有 2 列改成 3 列。红盘时在 KPI 下、memory pressure 之上插一条 disk alert。
  • 数值：主值用 formatBytes 后的已用容量（沿用 Memory 卡写法），右侧给百分比，下面 5px bar，与 Memory 一致；<80% 蓝、80–94% 黄、≥95% 红。
  • 口径：只统计本机「有意义的」卷——跳过 devfs、tmpfs、map auto_home、APFS 快照、/System/Volumes/VM；APFS 同容器（/ + /System/Volumes/Data）只算一次，页面上以 "merged" 行标注而不是隐藏。
  • 来源：新增 GET /api/server/disk（服务端 2s 缓存，客户端 5s 轮询），容量走 statfs；I/O 复用 hostmon 的 15s 采样（仅 Linux）。与 /api/server/processes 解耦，System 页两个请求并行、暂停时一起停。
  • 范围：v1 = 容量 + 卷列表 + I/O；不做内置目录扫描、不加清理/卸载操作。空间去向只留一个「Analyse largest folders」入口，主机装了 disk-usage-analyser 才出现（v2）。
  • 失败态：statfs 出错 → 卡片主值 — + meta "capacity unavailable"，不影响 CPU/Memory 与进程列表；一个可用卷都没有时整卡隐藏，而不是显示空卡。
