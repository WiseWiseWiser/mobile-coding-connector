# Alias

One CLI, several servers: an alias binds a name to a server and installs a
`~/.local/bin/<name>-agent` wrapper, so `xdev-agent exec …` talks to x.dev while
plain `remote-agent …` keeps the default domain.

```bash
remote-agent alias add xdev --server https://agent-xdev-aes562.xhd2015.xyz
xdev-agent config set --token-stdin        # save the token for x.dev
xdev-agent ping
remote-agent alias list
remote-agent alias which xdev
```

## Commands

| Command | Effect |
| --- | --- |
| `alias add <name> --server URL` | Record the alias + install the wrapper (`--binary`, `--bin`, `--no-install`, `--force`, `--dry-run`) |
| `alias update <name>` | Change `--server` / `--binary` / `--bin` (a server change needs no wrapper rewrite) |
| `alias delete <name>` | Remove the record and its wrapper (`--keep-wrapper`, `--dry-run`) |
| `alias install [<name>…] \| --all` | (Re)write wrappers into `~/.local/bin`, idempotent |
| `alias list [--json]` | Aliases with wrapper path and token state |
| `alias which [<name\|binary>] [--json]` | Resolve an alias: binary, server, token source, exec line |

State: `~/.ai-critic/remote-agent-aliases.json` (`{name, binary, server}` — no
tokens). The wrapper is a generated `#!/bin/sh` forwarder:

```sh
#!/bin/sh
# generated by remote-agent alias install (alias: xdev); do not edit
exec remote-agent --alias xdev "$@"
```

## How targeting works

`--alias NAME` names the server for any command; the token comes from the saved
domain for that server. `--alias` cannot be combined with `--server`/`--token`.

Wrappers only carry `--alias`, so:

- `alias update xdev --server …` takes effect immediately (no rewrite).
- tokens are never stored in a world-readable script.

## Tokens (config set)

Tokens belong to **servers**, not aliases. `config set` writes the server this
invocation points at — subcommand `--server`/`--alias` first, else the global
flags:

```bash
printf '%s\n' "$TOKEN" | xdev-agent config set --token-stdin   # preferred
remote-agent config set --server https://x.dev --token-stdin   # by URL
remote-agent --alias xdev config set --default                 # switch default
remote-agent --alias xdev config set --clear-token             # drop the token
```

`config set` preserves every other config field and never echoes the token.
`--token` works but lands in shell history and `ps`; prefer `--token-stdin`.

## Hard rules

| Rule | Detail |
| --- | --- |
| Wrapper ownership | Only files carrying the generated marker are overwritten/removed; anything else needs `--force` |
| Missing token | `alias add`/`list`/`which` warn and report `missing`; run the wrapper's `config set --token-stdin` |
| Retargeting | `alias update <name> --server URL`; `config set --server` with a different server is a conflict error |
| Not for local-agent | `alias` is remote-agent only |
