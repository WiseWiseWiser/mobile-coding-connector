E · 同类曲线：从结果页点任意分类进入（标题染上该分类的颜色）。副标题给「当前 / 占已用 / 峰值 + 日期 / 可回收」，图上一根轴、缺口就是缺口；底部逐次明细写 report <id>，可直接回看那天的完整报告。

机制要点（与实现一致）

  • 进度是服务端状态：~/.ai-critic/disk/job.json 每 2s 落盘 {id, started_at, phase, walked_bytes, files, no_access_dirs, percent, state}；前端运行中 1s、空闲 10s 轮询 GET /api/server/disk/analysis/status。百分比 = walked / (used × 90%)，封顶 99，结束才 100。
  • 停就是停：POST …/cancel 取消 context，walk 在 1s 内退出；last_attempt.outcome = cancelled，不写报告，历史曲线不会被半截数据污染。点停时若扫描刚好完成，返回 {"cancelled": false}，页面提示「the scan had already finished」。
  • 重复点击不排队：同一时刻只有一个全局 job；第二次 POST …/start 返回 409 + 正在跑的 job，前端直接接管进度卡。
  • 结果可追加：每份 Report（id = 扫描开始时间 20060102-150405）append 进 analysis.json，保留最近 50；最近 5 份保 entries 目录明细，更早只留 categories 汇总并置 entries_dropped。
  • 90s 软预算：超时不算失败，写一份 complete=false / truncated=true 的 partial 报告，前端用徽章标明。
  • 目录明细门槛：256 MB，每份最多记 40 个、页面显示最大 20 个；父目录若几乎只由一个子目录构成则只留子目录，避免 /Users 这类空壳占满列表；分类根目录（如 ~/Library/Caches）永不被自己的子目录挤掉。
  • 路径先归一到同一套坐标系：分类规则按 / 和 home 书写，而 macOS 的 walk 从 /System/Volumes/Data 起，所有真实路径都带这个挂载前缀；扫描、分类、记录、展示都先剥掉它（home 同步换算），否则每条路径都会落进 other，页面上也不会出现 ~/… 缩写。
  • 崩溃可恢复：启动时发现残留 job.json → 记一条 interrupted 尝试（"the server stopped before the scan finished"），不会永远显示「正在扫描」。
  • 曲线数据来自报告本身：GET …/reports?limit=50 一次返回所有分类汇总，趋势页不再发 N 次请求；分类缺失 → 断线，schema 变化 → 分段各自一根轴。
  • 两个时间分开给：last_completed_at（入口卡、结果页）与 last_attempt{at, outcome}（运行页副标题、中断/失败提示）；超过 24h 未跑才在页内提示 stale。
